# V1.1 复杂表格结构恢复

起点 main / 4983a6c。用户已有未跟踪 gradle/gradle-daemon-jvm.properties 保留。旧历史不改写，三份外部产品文档只读。

## 审计与依赖

GridDetector 原先要求 3–25 条竖线、至少16像素间距、完整边线和单段85%以上覆盖；TableCandidateAssembler 固定第一行生成字段，按规则小格分配 OCR，并把全空行跳过。
这使合并表头、30+列、局部断线、倾斜和数据区不占整图的表格被当作结构失败，甚至无法提供人工确认。
SourceRegion 为 EXIF 正向原图归一化矩形；保留该契约，结构图另保存真实四角与逻辑分割用于覆盖显示及文本归属。
CandidatePage、RoomStructuredRepository、Validation/Review/导出继续作为唯一数据链。

## 分阶段范围

1. 几何结构：扩展 TableGrid 为有边覆盖证据与矩形合并的图，分离结构结果、Header 范围和 OCR 内容；轻微方向/透视使用线的交点，不引入 CV 框架。A–K 确定性 fixture 验证。
2. 持久处理：正式 Room v6 migration 保存页面结构草稿/确认及任务内模板；字段保存 headerPath。结构确认后才进入候选持久化，后页严格几何/表头匹配后复用。
3. 作业 UI：原图覆盖边界、分割、Header与合并；最小数值编辑增删分割、Header范围、确认及后续继续处理。来源关系不另建平行版本。
4. 综合验证：A–K 与等价现实复杂表格样本/指标，旧质量链完整回归，Debug/Lint，设备可用时验收，记录实际边界后独立提交。

## 可靠性原则

结构复杂不等于图片不可用。检测到候选但边界/合并/Header不确定时返回 STRUCTURE_REVIEW_REQUIRED；只有缺乏有效候选或无法读取才 SOURCE_UNUSABLE。
AUTO_ACCEPTED 仅用于有充分几何和表头证据的普通结构。缺线与合并不能总是自动区分，必须保留人工拆分/合并途径。
数据区跨列合并不能假装为多个独立识别值；结构确认时明确如何投影到字段，保留同一逻辑 Cell 的来源区域并标为需值复核。
同模板复用不根据一个 OCR 文本猜列界，禁止给明显异结构页面强行套用首张模板。
合成图只能证明确定性几何和状态行为，不能替代真实照片/设备验收。
