# V1.1 结构恢复：实现、验证与限制

日期：2026-09-09。以main / 4983a6c的V1质量链为起点。产品外部文档只读；以下“自动验证”不等同于真实照片或手机验收。

## 以前为什么失败，现在如何处理

旧实现按完整水平/竖直网格生成小格，限制列线数量、间距与连续覆盖，并固定首行为字段。合并表头会成为“缺边”，多行表头被混入数据，30+列超出范围，轻透视或元信息改变线条分布后直接失败。

当前沿用唯一的TableGrid和CandidatePage链路：

- 几何线投票、连接区域、四角映射恢复主表；OCR仅提供文字、框和可靠性，不生成列分割。
- 缺失局部边线形成连接证据，典型矩形组件保存rowSpan/colSpan。非矩形或部分缺线保守要求核对。
- Header保留起止行和逐列headerPath，支持多层与换行。文本可辅助建议数据起点；含数字的中文表头不再仅因数字被当作数据行，相同层级名称不会被去重丢失。
- 高可靠结构AUTO_ACCEPTED；合并、表头或归属歧义进入STRUCTURE_REVIEW_REQUIRED；找不到有效几何或文件无法使用才SOURCE_UNUSABLE。
- 含文字PNG回归发现并修复了降采样误差造成的假缺边、重复中文字行造成的假横线、合并内部文字造成的假边段。

这使下面的复杂正例可以准确恢复并进入人工确认，不能据此宣称任意人眼可读表格都已支持。

## 用户实际可操作的范围

任务详情的“确认 / 调整表格结构”和来源结构异常均可打开确认页。页面显示原图，覆盖外边界、行列、蓝色Header与橙色合并区域，支持缩放、平移和复位。

编辑以明确数值完成：四角百分比调整区域；表头首末行；增删行列百分比分割；填写或删除矩形合并范围；修改每列分层字段路径。输入不完整会明确提示覆盖图仍为保存版本，不伪装调整成功。加载原图时固定占位尺寸，避免图片到达后把确认按钮推离点击位置。

保存草稿保留OCR证据、结构和修订号，重建页面后可恢复；点击普通“继续整理”不会重新识别覆盖草稿。确认后事务生成原有动态Schema/Rows/Cells，继续质量检查和后台剩余页面。调度失败明确提示结构已经保存，允许回任务继续。

首次歧义页暂停批次，确认模板后后页在各自四角内按相对列位置对齐，允许缩放、位置与轻透视差异以及少量缺线。匹配后仍核对完整Header路径。明显异表产生SCHEMA_MISMATCH；新出现的数据区合并或文字跨界要求页级确认；缺列恢复不能丢弃原有合并证据。

## 持久化与质量链保护

Room正式v5→v6迁移新增page_structures与field_definitions.headerPath，不重建旧数据库。冻结v5升级测试保留已有原值、人工值、字段名称和任务状态；早期迁移继续执行。

Structure→CandidatePage→RoomStructuredRepository→Validation/Review→Provenance→Duplicate→XLSX仍为同一条数据链。未确认结构阻止标准导出。字段显示名称编辑不会改写原始Header路径；原图不复制，来源坐标保持EXIF正向原图约定，四角投影提供局部包围区域。

结构覆盖人工结果需要明确授权，成功后清除该次授权；旧修订号不能覆盖新草稿。数据区合并只在左上slot存放候选内容，其他覆盖slot不自动复制业务值，所有覆盖slot标为需要值复核。结构确认不是内容确认。

## 真实材料限制

- 依赖可辨认的表格线和足够长的共线片段；无边框、强反光、严重模糊、大面积缺失或密集强摩尔纹仍可能失败。
- 方向搜索为有限斜率约±0.12（单方向约7°），不是任意旋转/重透视矫正。EXIF恢复保留；真实折纸、弯曲页面不在当前模型内。
- 自动Header建议为启发式；英文数字表头、纯文字数据或非常深的表头可能需要指定范围。跨Header/数据的合并必须先调整，不能直接确认。
- 测试覆盖36列，模型容量上限128列/500行不代表这个上限已在手机上验证；数值编辑窄列复杂表的效率也未做用户计时。
- 模板仅当前任务内复用，并保守比较Header文字层级。OCR差异可能要求额外核对，不提供跨任务模板管理。
- 数据区合并的业务传播含义由用户决定；XLSX输出结构化记录和复核信息，不重现原纸复杂排版。
- 本轮无真实拍摄/手写准确率、处理耗时、系统杀进程恢复或Excel/WPS实际打开的新增验收结论。
