# 屏摄原图问题跟进（2026-09-10）

用户反馈：同一张屏摄表格在手机上“一直整理中或直接退出”。此记录补充V1.1，不能继续用合成样本通过代替实际可用性。

## 已证实的故障

使用用户提供的4072×3070 JPEG，按生产SourceImageLoader同样的1/2采样解码为2036×1535，在Robolectric NATIVE下运行真实GrayImage/GridDetector。
修复前：固定205阈值把灰背景与屏幕纹理当作线条，341条横线、191条竖线候选形成一个大连接区域；竖线超过128列结构容量，直接返回SOURCE_UNUSABLE。OCR尚未运行。

这是结构拒绝的直接证据，并不是手机崩溃原因的证明。设备历史退出记录只见USER REQUESTED/FORCE STOP，没有本次崩溃栈；设备已安装APK哈希与上轮最终构建不同，版本未对齐。

## 本次修正

- 32像素局部块的背景分位数与对比差决定线条阈值，保留白底浅线能力，避免屏摄灰底被整体二值化为前景。
- 以长线得分选择斜率随位置变化的共线族，容忍轻透视，抑制任意方向纹理。单条OCR文字不参与定位。
- 去除远离主线的零散文字/工具栏片段；列须有足够行交点，避免侧栏把表格与软件界面连成整屏。
- 强横线族中的孤立弱文字横排只作为不确定证据，排除时明确要求人工核对；保留用户补回分割的入口。
- 对粗斜率投票做像素回归细化，降低长列的累积位置误差。
- 外交点只略超图边时保留截断候选并强制结构确认，不再仅因少量裁边把整页判为不可用。未放宽行列容量上限。
- 结构计算内部加入取消检查；生产适配器设20秒结构计算上限，超时产生STRUCTURE_WARNING并结束本页，不伪造成功。图片读取及OCR原有超时继续生效。
