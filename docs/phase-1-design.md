# Phase 1：来源页面可靠接入

## 范围与产品基线

本阶段只建立任务与真实来源页的可靠关联，不实现识别、表结构生成、Validation、Review 或导出。
保持单 app 模块，不新增库或架构框架。Phase 0 提交和 v1 Schema 均保留。

用户提供的《用户手册》《操作指南》《最初测试方案》V0.1 是产品目标基线，
不是要求本开发阶段完成完整 V0.1。三份原文由主对话维护，本次未修改。

## 实际依赖

```text
任务详情 / SourceSection
  ├─ SourceImagePicker → 官方 OpenMultipleDocuments + CATEGORY_OPENABLE
  └─ SourceViewModel（绑定当前 Navigation entry 的 taskId）
        └─ SourceRepository
              └─ RoomSourceRepository（应用级单实例 + Mutex）
                    ├─ Room v2 / SourceDao / TaskDao
                    └─ SourceAccess → AndroidSourceAccess → ContentResolver
```

SourceViewModel 随导航项管理生命周期。来源列表通过 Flow 观察数据库，数量取列表大小，Task 没有 sourceCount。
来源读取失败与空列表分开，返回前台和点击“重新检查来源”均重新读取权限和来源访问状态。
选择器回调排队执行，不会因为 ON_RESUME 检查正在进行而丢掉用户选择。
Activity 重建由 Activity Result Registry 和 Compose 的保存状态恢复回调；结果始终交给原任务绑定的 ViewModel。

## 数据结构与迁移

Room 从 v1 升级到 v2，仅增加 `source_documents`：

| 字段 | 含义 |
| --- | --- |
| id | UUID，移除其他页和重新排序时不变 |
| taskId | 外键到 digitization_tasks.id，RESTRICT 防止绕过来源管理删除父任务 |
| sourceUri | 系统返回的原始 content URI 文本 |
| pageIndex | 从 0 开始的连续顺序，UI 显示为第 1、2…页 |
| status | AVAILABLE / UNAVAILABLE |
| createdAtEpochMillis | 来源加入时间，映射为领域 Instant |
| displayName | 文件提供者给出的可选名称，仅作页面摘要 |

唯一索引 `(taskId, sourceUri)` 防止重复关联；`(taskId, pageIndex)` 防止页序冲突。
同 URI 可以属于不同任务。当前去重只比较相同 URI 字符串，不判断别名 URI、内容相同或相似图片。

按系统回调给出的顺序去重、追加；不声称此顺序必然是用户点击顺序。
移除后在事务内按原页序逐项向前填补空位，再次添加从末尾追加。没有拖拽重排。
添加与移除的来源写入、页序和 Task 状态在同一个数据库事务内处理。
第一张来源加入后为 CAPTURING，最后一张移除后回到 DRAFT；仅允许这两个状态编辑来源。
可访问性不等于数据可靠性，也不会触发 READY_TO_EXPORT。

迁移只创建新表及索引，不改写或删除旧任务；旧版导出 Schema 是迁移测试的输入。
Room 在打开迁移后的文件数据库时再次验证结构。未使用 destructive migration 或删除用户数据库的替代方案。

## 长期读取与低缓存

使用 ACTION_OPEN_DOCUMENT、多选、image/* MIME 过滤和 OPENABLE 限定，不请求相机或广泛存储权限。
仅调用 takePersistableUriPermission 的读取标志，并检查 persistedUriPermissions 中确有读取授权。
通过 ContentResolver 真实打开只读文件描述符；MIME 非图片、空文件、无法打开或不能持久授权的项明确拒绝。
查询可选文件名，描述符及 Cursor 使用 use 关闭；不解码图片、不复制原图、不建立磁盘缩略图缓存。
“可访问”只表示检查时拥有持久读取授权且能打开该来源，不表示图片清晰、完整或结构正确。

URI 授权与 SQLite 无法组成原子事务，因此先申请权限、检查来源，再事务写入可接受的来源。
授权申请完成后再次核对最终授权集合，防止系统在批量授权中回收较早授权而造成假成功。
本任务已有来源若因此失去授权，保留记录并标为 UNAVAILABLE。
批量输入中不可接受的项逐项报告，其余有效项一次性入库；数据库写入失败则这批入库整体回滚。

移除来源只调用数据库 DELETE，不调用文件提供者的 delete，不删除原图。
只有全库已无关联的 URI 才释放本应用的持久读取授权；其他任务仍引用的 URI 不释放。
失败、取消后的未引用授权会清理；进程突然退出或提供者超时可能留下授权，后续来源操作会再次核对并释放。
若清理失败，用户看到“部分清理未完成”，页面移除本身不回滚。
此清理规则以“当前应用所有持久读取授权都属于来源管理”为前提；后续若其他功能持有此类授权，必须扩展所有权判断。

单次提供者调用设有 10 秒超时，并向 Android CancellationSignal 传递取消。
忽略取消的文件提供者可能晚些返回，后台调用返回后仍关闭描述符；应用侧停止等待，不把超时视为成功。
批次总时长与页数、文件提供者速度有关，不承诺固定时间完成。
进程在导入完成前终止时，整批写入可能尚未提交；重新选择可重试，唯一约束防止重复记录。

## 来源失效与恢复

重新进入任务时读取实际持久权限，再尝试打开来源。
撤权、文件移除、提供者离线或读取超时会使已有页面变为 UNAVAILABLE，页面 ID、页序、计数保留。
恢复原文件后可“重新检查来源”；不能恢复时“移除”后重新添加。
没有重新绑定 URI 的专用按钮。再次选择同任务已有 URI 会提示重复，不隐式替换旧关联。
云盘提供者可能需要联网；应用自身没有云服务，也不能保证云端来源离线可读。
